3 core adjustments

Instead of searching randomly in an unsorted array, sorting takes O(n log n) time upfront. Once numbers are arranged in ascending order, we unlock monotonicity: if our triplet sum is too low, we know with mathematical certainty that incrementing the lower pointer will increase the total.

Rather than checking every pair with nested loops (costing n × n inner operations), we position a left pointer at the start and a right pointer at the end. In each step, we either shift left++ or right--. This squeezes inner iterations into a single linear O(n) pass.

result.contains() performs an exhaustive sequential lookup over the accumulated answer set on every hit, resulting in degenerate quadratic memory lookups. Since the array is sorted, duplicate values cluster together. Simply skipping identical neighbors (nums[i] == nums[i-1]) eliminates duplicates in O(1) time.
